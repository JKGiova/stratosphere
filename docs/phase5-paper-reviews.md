# Authored account budget and risk reviews

Status: **private advisory increment over existing internal authored journals**. This adds two model roles and Reports integration. It does not set up an account, change capital, approve a mandate, invoke Liquid or run a paper service. The [full Phase 3–5 ledger](phase3-5.md) remains in progress.

## Explicit request and privacy

`/paper-review` requests a budget proposal followed by a risk assessment. `Review the authored paper account budget and risk` reaches the same operation through a deterministic, narrowly matched bridge. An unrelated model-generated route cannot initiate this disclosure. General chat, source review and strategy selection do not send an account snapshot. Onboarding states that this explicit request sends the authored financial snapshot to the selected model provider; that provider's configured pricing applies. Development verification uses an already installed local Ollama model, without paid calls or model downloads.

`/paper-reviews` lists retained attempts. `/paper-review-show <complete-review-id>` opens a verified report in Reports. Reports also lists completed, integrity-checked reviews across restart and supports the existing responsive layouts and keyboard navigation. Failed or damaged attempts cannot appear as completed reports. `/cancel`, Ctrl+K and quitting cancel the worker; a completed budget remains retained if the risk stage fails or is canceled. There are no automatic retries, corrective model loops or implicit approvals.

The default journal is `<research-state>/paper/account.sqlite3`; private reports live in `<research-state>/paper-reviews`. These commands do not accept arbitrary journal paths. There is no account-creation/onboarding command in this increment. If that internal journal does not exist, review fails before creating an account or making a model request. An ordinary installation without an authored development account will therefore report that no journal is configured.

## Frozen application observations

The journal is opened using a SQLite read-only URI and query-only transaction. Its event chain is replayed with the same exact decimal precision as the ledger. Current journal versions 1–3 are supported without construction, migration, funding or writes. A snapshot retains the authored account origin, complete journal digest, capture time, each instance's IDs/cap/cash/base/reservations/pending orders, stream review/fault status, indexed application facts and available deterministic diagnostic metrics. Authored quote recency is evaluated at capture and cannot precede its retained receipt time; it remains a caller-declared observation, not authenticated price, clock or executable liquidity evidence. Missing quotes remain missing. Execution eligibility is always false.

Each role has a stable ID derived from this local authored account ID and its role. These are private local identities, not verified provider ownership or shared-user isolation. Every request gets a fresh snapshot and one-shot role contexts; previous reports, strategy conversations, raw source text, Liquid catalogs and arbitrary journal reason text are not loaded into either prompt. The risk model receives the same frozen snapshot and the validated budget proposal, with the proposal treated as untrusted text. This is not an ongoing agent conversation or service.

Application code enforces exact instance coverage, finite nonnegative eight-decimal amounts, each retained capital cap and the aggregate starting-capital ceiling. Any instance with held base or a pending order must retain its full existing allocation in the proposal. Flat, unreserved instances may receive a proposed amount from zero through their cap. Zero is advice only; it does not deactivate an instance. Risk findings must cover every instance, use known categories and select known application fact indices. Duplicate or unknown references, invented approval fields and malformed questions fail validation. A valid reference does not prove that the model's interpretation follows from it.

## Reports and authority

Versioned basis and review contracts bind the account, snapshot digest, model reference, role IDs, both proposals and the loaded prompt/schema contract digest. That last digest identifies the interpretation contract, not an executable attestation. Files are written exclusively with private permissions; a final manifest binds request, basis, budget and review. Readers revalidate proposals and cross-file references as well as hashes. These local hashes detect inconsistent artifacts, not malicious host replacement or provider signatures. Known configured credentials are checked in encoded and decoded data before model use/storage. OAuth sessions and service credentials are not inputs.

Capture and review times remain distinct. A journal change during generation retains a historical report with `state_changed_during_review=true`; replacing the account origin fails the attempt. Neither a successful review nor an unchanged journal becomes current execution approval. Reports distinguish application facts/metrics from model prose, label all interpretations unverified and display both role questions and missing verification. Proposals have no operation path to allocation changes, reservations, delivery claims, provider tools, SQL or orders. The existing [reviewed decision gates](phase5-signal-decisions.md) continue to work without these models.

Measured final regression, installed-wheel and live-model outcomes are recorded in the [acceptance ledger](phase3-5.md); structural success is separate from interpretation quality.
