# Strategy-agent development

The orchestrator hands a complete sealed intake to an implementation specialist. A validated formal
definition gets an exact registered strategy and stable agent; that agent owns compilation,
backtests and measured-result revisions. The orchestrator does not place orders. Trading remains
outside this service, under the separate final-approval/account/position-risk workflow.

## Entry and ownership

A newly created intake with all six rule categories and no unresolved questions can hand off
automatically. `/develop <brief-id> [focus]` explicitly starts the same path; `/development-show
<campaign-id>` opens complete reports or retained partial evidence. Tests/Reports include development
campaigns. Reading a report never starts a worker or inference call.

Initial formalization must map entry, exit, market, timing, sizing and risk to exact intake rule
indices. Citations prove the passages exist, not semantic conformance. Missing or unsupported
behavior stops with retained questions/failures, rather than a substitute implementation.
Definition and code remain explicitly unverified conversions of their source.

An existing developed strategy can request further research through its own agent. Its exact
registered definition is pinned before inference and must remain the new baseline. Changes belong
to explicit behavioral variants. Private histories and account/credential diagnostics are excluded
from implementation/refinement contexts. Related candidate results retain exact child IDs, scopes
and variant lineage; unrelated strategy histories are never supplied.

Exact behavior reuses the same registry owner/agent. Exact re-delivery of an intake/focus/parent/code
request reuses its campaign without replenishing budget. Interrupted, failed and canceled campaigns
cannot automatically resume; an explicitly changed intake/focus creates a distinct campaign.

## Executable language and code

The model proposes a validated `strategy/1` expression program, not arbitrary Python. Supported
signals combine SMA, EMA, Wilder RSI, OHLCV fields, arithmetic, comparisons, Boolean conditions and
crossovers. Programs have one hourly or daily timeframe, fixed units, one long position, closed-bar
evaluation and next-available-open synthetic market fills. Exit rules are evaluated even when
entry market filters are false. Initial exposure is flat; terminal exposure remains open and is
marked at the final close. No reinforcement, leverage, shorts, intrabar path or native stop order
is implemented here. Unsupported stop/indicator/multi-timeframe behavior must remain blocked.

SMA uses exact rolling means. EMA uses an initial period-length SMA then alpha `2/(period+1)`.
Wilder RSI seeds average gains/losses from the first period of price changes, then applies Wilder
smoothing; its flat-market value is 50. Signal arithmetic uses exact rational numbers. These
conventions do not establish equality with a paper, Pine or another indicator library.

The application compiles the definition to `strategy.py`, a Python specialization of its packaged
signal runtime. It is executable inside the pinned application and Nautilus adapter, not a standalone
MT5 EA. The generated bytes, concrete definition, runtime implementation and input snapshot are
pinned before each child starts. The worker only loads bytes exactly equal to compiler output;
modified/generated-from-elsewhere/acquired Python cannot pass this gate. There is no general
model-controlled shell/import/file/SQL facility. Preserve the v1 compiler output and historical
readers when introducing a future compiler format.

## Frozen research and iteration

One application-authorized campaign freezes:

- The source brief, formal definition, exact owner and implementation digest.
- At most four explicit Yahoo symbol/asset-class/interval/window/quantity/cost targets, each with
  a market hypothesis. Quantity/cost/window changes cannot appear inside a revision.
- At most three programs: baseline and two justified behavioral revisions.
- At most twelve candidate cells and twenty-four consumed native-start slots, including base and
  doubled-cost simulations. Failed starts remain consumed.
- At most three specialist model calls: initial definition and two refinement calls. Research-run
  execution has a 1,200-second overall deadline; individual native/acquisition workers have
  180-second limits. Preparation and source intake have their own finite stages.

Data is acquired once per target and verified/reused for revisions. Every blocked target, failed
candidate, source/code artifact, reservation and completed result remains retained. A candidate
has an exact fixed instrument/timeframe definition and separate registry lineage. Parameter/rule
changes get new behavior identities. Repeated behavior is not another native experiment.

After measured results, the same agent can change indicators, entry/exit expressions or filters,
or stop. Warmup may change within 1,024 bars for changed periods. Other timing, sizing, universe,
data semantics, execution, assumptions and missing-data rules stay frozen. Refinement receives
bounded measured summaries, not credentials, broker observations, full trade arrays or local
artifact paths. Cancellation kills the child and retains consumed reservations; startup recovery
marks abandoned jobs interrupted without replay.

## Data and report interpretation

Historical acquisition uses the same strict Yahoo normalization as existing research, with a
separate generic price-snapshot contract. Equity/ETF, spot crypto and fully funded FX identities
remain separate from MT5 CFD instruments. Corporate-action windows are blocked; dividend/split
accounting is not silently omitted. Point-in-time stock membership, delisting, corporate-action
execution, interior sessions, funding, FX rollover and variable capital allocation are unverified.
Missing-volume strategies fail when their rules need volume. `abort` gap policies reject observed
gaps; `skip` retains/discloses them without inventing bars or session calendars.

The report retains every attempted program/market pair, base/stress results, generated code and
formal definitions. It ranks the frozen samples by stress net return minus stress drawdown.
Review filters require positive base and stress return, at least five completed stress trades and
stress drawdown no greater than 20%. No candidate is selected if none passes. Fixed quantities and
declared windows affect comparisons; this does not validate a future variable-size portfolio policy.

Stock summaries identify the best *sampled* candidate per symbol. Yearly equity changes and buckets
based on the previous twenty bars' direction are descriptive same-sample attribution. They do not
prove predictive regime suitability. Revisions saw these results: there is no independent holdout,
global-best claim or profitability-only deployment authority. A selected case is a candidate for
human review, not an approved finished MT5 strategy.

## Evidence

Tests cover exact SMA parity, EMA/RSI seed arithmetic, compiler tampering, source/data/owner pins,
finite budgets, no replay, cancellation, partial evidence, revisions and the UI handoff. Actual
Nautilus runs exercise generated SMA/EMA/RSI code and an equity program in a credential-free child.

A logged public-data integration check on October 29, 2026 used AMZN/TSLA daily Yahoo history for
2025, two RSI programs and eight base/stress native starts. All four candidate cells completed.
Source interpretation and model replies in that check were authored fixtures, not live-model
inference. Private artifacts are under `reports/strategy-development-20261029`; no broker account
or orders were used. Live-model implementation reliability, faithful source conversion, independent
validation and MT5 execution remain separate verification gates.
