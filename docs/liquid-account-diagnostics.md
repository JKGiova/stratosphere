## User operation

After `/liquid-connect` completes with read access, `/liquid-account` explicitly calls **only `get_account`**. Connecting, checking public metadata, browsing/exporting the catalog, opening an old diagnostic, selecting a strategy or chatting never invokes it automatically. No model configuration is needed; Escape dismisses inline model setup if necessary. The command accepts no account, URL, tool name, scope or free-form arguments. The application supplies one fixed intent: show the trading-account address without changing settings.

Focus shows the outcome, capture times, limitations and a private observation path. `/liquid-account-reads` lists attempts; `/liquid-account-show <complete-read-id>` verifies and opens a historical diagnostic online without restoring a connection. Private files live under `<research-state>/liquid-accounts/<id>/`. Share only a status or artifact path for development verification, never credentials or account response bodies.

The existing callback and current OAuth grant still authorize only `read`. Only the short-lived access token is sent as a bearer credential. The negotiated MCP session identifier and monotonically advancing request counter stay in memory. Grant/session values, including code, PKCE/state and discarded refresh/client secrets when present, remain only as in-memory redaction guards; there is no refresh implementation, credential persistence or scope fallback. Disconnect, canceling connector work and quitting forget the session; memory forgetting is not a cryptographic wipe or provider-side consent revocation.

## Protocol and schema boundary

The separate account reader uses the initialized, complete catalog session. The catalog transport's own operation allowlist remains initialization, its notification and tool listing. The new reader has one literal `tools/call` site, with the name `get_account` and fixed arguments. There is no generic tool dispatcher and no model route to this operation.

Before dispatch, the captured definition must match the reviewed input/output structure. The input permits only optional `user_intent` with the reviewed string bound. The output requires exactly a string `tradingAccountAddress` and the literal role `trading-account`. Descriptions/titles/comments and the reviewed draft schema declaration are descriptive data; annotations never grant invocation permission. Unknown validation keywords, references, required inputs, broader fields or absent outputs block the call. Schema references are not fetched. The actual supplied catalog matches this guard, but a snapshot/schema match does not attest to server behavior or a later contract change.

The [pinned MCP tool specification](https://modelcontextprotocol.io/specification/2025-06-18/server/tools) distinguishes structured result data, optional text content and tool execution errors. The reader validates the JSON-RPC result ID/type and reuses the fixed resource, bearer token, negotiated session ID and protocol version. A changed returned session ID, expired/replaced session, protocol error or unsupported server request fails without automatic retry, sign-in, confirmation or other tool invocation. A bounded SSE result may finish before the server closes its stream; no subscription, resource fetch or server callback is enabled.

## Evidence and limitations

Before network dispatch, an exclusive private request and reviewed definition are recorded with a `dispatching` event. Cancellation or failure retains that uncertainty: the read may have reached Liquid. It cannot truthfully be described as an unsent request. A second overlapping account read in the same session is rejected. Nothing retries a consumed attempt in the background; a later explicit command creates a new attempt.

An observation records local request/receipt times, catalog/definition/result digests, typed provider-reported fields, exact plain provider text and status flags. A final manifest binds the request, definition and observation. Files use 0600 and new directories use 0700 on Linux/macOS. Root symlinks or permissive diagnostic roots are rejected; readers check symlinks, file digests, fixed contracts and cross-file references. These are local consistency checks, not provider signatures, authenticated account ownership or tamper-proof host storage.

Only the supported structured fields become a reported identifier. It must be a nonempty, bounded printable identifier; no address-format, chain, wallet-control or deposit-destination claim is inferred from the provider's generic string schema. There is no text-only fallback. Non-JSON prose, confirmations, contradictory text, errors, unknown metadata and non-text content remain `requires_review` or `provider_error`. Typed address fields may still be retained as a candidate, without linking or authority. Provider text is shown in a literal, safely fenced block with links disabled. No returned URL, widget, image or resource is opened. Unknown response metadata/unsupported structured fields are omitted; only the received result digest identifies that unretained envelope. The digest cannot reconstruct or independently verify omitted bytes.

Known access/grant/session/model credentials are rejected before storing the observation, including decoded/escaped JSON text. Request headers and raw OAuth responses are never observation fields. Unsupported metadata is not copied into an artifact. As with catalog exports, unexpected plain provider text remains private diagnostic material and must not be published. Diagnostics do not enter model prompts, strategy histories, research jobs, shared database records, native workers or Positions.

Every record fixes ownership verification to false, environment to unverified and execution authority to none. `address_reported` means supported fields were received; it does not prove paper mode, account ownership, feed access, balances or readiness. Historical records cannot recreate an OAuth session or satisfy a future mandate. The wallet-wide simulator setting observed in the catalog is still insufficient per-request protection against another client switching to live mode.

The 54 new account/command/TUI checks passed. An independently installed wheel passed two fresh processes, private file checks, source equality and configured-credential/private-state exclusion; Focus was keyboard-tested and visually inspected at 180×48 and 45×12. Still required: account ownership/environment checks appropriate to future linking, authenticated application identity, feed entitlement and semantics, per-request paper isolation, transport/reconciliation and sustained runtime verification. The account-linking and paper-adapter acceptance items remain unchecked.
